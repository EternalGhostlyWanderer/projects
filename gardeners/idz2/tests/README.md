# Набор тестов «Нелюдимые садовники»

Запускать из корня проекта:

```sh
make clean
make
make test
```

`make test` собирает обе версии приложения и запускает `tests/run_tests.sh`.
Служебные файлы тестов (журналы, выводы) пишутся в `test-results/`. Если все проверки
прошли, каталог очищается (остаётся только `examples/` с примерами для отчёта); сохранить
файлы можно так: `KEEP_RESULTS=1 make test`. При ошибках остаются все файлы, а список
неудачных проверок — в `test-results/failures.txt`. `make clean` удаляет `test-results/` целиком.
Итоговые строки скрипта: «Успешно», «Ошибок», «Пропущено».

Проверки сигналов во время диалога используют FIFO (именованный канал) во временном каталоге
Linux. Если FIFO недоступен, такие проверки печатают `SKIP` и пропускаются, а не падают.

## Что проверяется

Тесты интеграционные: запускаются собранные `garden_sem` и `garden_cv`. Сверх кода
завершения и подстрок используется независимый разбор журнала (`tests/check_log.sh`).

| Группа | Проверки |
|---|---|
| Командная строка | справка; значения вне диапазонов (`-W`, `-H`, `-p`, `-v`, `-t`, `-k`); нечисловые значения; `-a/-b` без запятой, вне сада, на препятствии; неверные маршруты `-A/-B`; неизвестный параметр; параметр без аргумента; лишний аргумент; предупреждение при `-W/-H/-p/-r` вместе с `-m` |
| Начальная карта | садовники нарисованы в стартовых клетках: по умолчанию, при `-a/-b`, при углах `TR/BL` (обе сборки) |
| События журнала | старт, переход, прибытие, начало и конец обработки, пропуск препятствия, недостижимая клетка, освобождение клетки при выходе, статистика, число сообщений о завершении; вывод на экран совпадает с журналом |
| Порядок обхода | на карте из двух изолированных зон проверяется точная последовательность клеток каждого садовника для `TL:rows/TL:cols` и `BR:rows/BR:cols` (змейка) |
| Тупик | встречные садовники в коридоре длиной 2–6 (без и с `-o`): код 2, сообщение «ТУПИК», причина, диагностика с координатами |
| Инварианты при встрече | 4x4 с пересекающимися маршрутами, 6x6, старты рядом, разные скорости, случайные сады (6 зёрен, без и с обходом), острова: встроенный контроль инвариантов («нарушений: 0») и независимая проверка журнала |
| Недостижимые клетки | карта с изолированной клеткой: код 0 и строка «(2,4) — недостижима…» |
| Препятствия | зерно воспроизводит сад в обеих сборках, разные зёрна дают разные сады, `-p 0` без препятствий; пруды `~` и камни `#` |
| Режимы вывода | `-v 0/1/2` |
| Скорость/время | разные значения для садовников; одно значение для обоих |
| Журнал и вывод | недоступный журнал, совпадение с выводом, закрытый канал вывода (SIGPIPE) |
| Файл конфигурации (`-f`) | минимальный, полный (старты, маршрут, препятствия, комментарии), многострочный, CRLF, `true/false`; доля из файла; перекрытие параметрами командной строки; диалог берёт умолчания из файла; ошибки: нет файла, пустой, мало значений, нечисловые, размеры и доля вне диапазона, время выше лимита, неверный флаг обхода, неполные старты, мусор, нечётные координаты препятствий, препятствие вне сада и на старте, старт вне сада, одинаковые старты, каталог, `-f` без аргумента |
| Размер | сад 60x40 |
| Диалог ввода | пустой ввод, закрытый stdin, `/dev/null`, EOF посреди ввода, последняя строка без `\n`, неверные значения и повторы, 5 неверных подряд, CRLF, пробелы, строка 20 КБ, мусорные байты, карта и старты через диалог, ошибки старта; **SIGINT и SIGTERM во время диалога (код 3)**, SIGUSR1 во время диалога, закрытие ввода во время ожидания |
| Сигналы | SIGINT (обе сборки), SIGTERM, SIGINT во время обработки (прерванные клетки не засчитываются), SIGUSR1 (карта без остановки) |
| Журналы | существование и непустота журналов |

Независимая проверка журнала (`tests/check_log.sh`) по событиям проверяет, что:
два садовника не занимают одну клетку (с учётом занятости обеих клеток во время
перехода); препятствия не посещаются и не обрабатываются; клетка начинает обрабатываться
не более одного раза; каждое «начал обработку» закрыто «закончил» или «прервана»;
число «закончил» совпадает с итоговой статистикой.

## Коды завершения в тестах

`0` и `2` допускаются там, где итог зависит от расписания потоков. Строго проверяются:
`1` — ошибки параметров и карт; `2` — тупик в коридоре; `3` — сигнал; `0` — карты с
изолированными зонами и сады, где садовники не могут заблокировать друг друга.

Проверки ожидания и обхода на сетке 4x4 зависят от расписания потоков; обход повторяется
до пяти раз. Инварианты при этом проверяются в каждом запуске.

## Запуск под санитайзерами (необязательно)

```sh
make asan && make test      # AddressSanitizer + UBSan: память и неопределённое поведение
make tsan && make test      # ThreadSanitizer: гонки данных (флаги вроде sig_stop могут давать ожидаемые замечания)
make clean && make          # вернуться к обычной сборке
```

Замечания санитайзеров появляются в `test-results/*.out` и в выводе тестов; код завершения программ при них может быть ненулевым, поэтому часть проверок может падать — смотрите первое замечание в `failed_*.txt`.

## Примеры для отчёта

```sh
sh tests/make_report_examples.sh
```

сохраняет выводы характерных запусков в `test-results/examples/` (обычный запуск, положение
садовников, ожидание, обход, пруды, изолированные клетки, тупик, вторая реализация, SIGINT).

Результаты последнего запуска вписываются в `tests/RESULTS.md`.
