# Тесты модели Qwen / Alfa Signal

Набор скриптов для проверки API организаторов, моделей и входных данных (CSV, PDF). Скрипты лежат в `backend/scripts/`, код frontend они не затрагивают. Все профили компаний в тестах **синтетические**.

## Что внутри

| Файл | Что делает | Обращается к API |
|---|---|---|
| `common.py` | Общий код: клиент, чтение `.env`, JSON Schema, разбор JSON, стили отключения рассуждений. Сам не запускается | нет |
| `test_connection.py` | Проверка подключения; `--try-all` находит рабочий способ отключить рассуждения | да, 1–5 коротких запросов |
| `test_business_analysis.py` | Один бизнес-анализ с проверкой по схеме `docs/contracts/business_analysis.schema.json` | да, 1 запрос |
| `compare_models.py` | Сравнение Qwen, DeepSeek, GLM, Gemma и Kimi на синтетических кейсах с проверкой по схеме | да, до 10 запросов |
| `test_tool_call.py` | Возвращает ли модель реальный `tool_call` (функцию не выполняет) | да, 1 запрос |
| `test_csv.py` | Структура CSV: колонки, типы, пропуски. Значения строк не печатаются | нет |
| `test_pdf_text.py` | Есть ли в PDF извлекаемый текст | нет |
| `test_pdf_chart_vision.py` | Отправляет страницу PDF как изображение модели | да, 1 запрос |

## 1. Установка

Откройте терминал в корне проекта. Если в проекте уже есть общее окружение, используйте его и не создавайте второе.

### Windows PowerShell

```powershell
python -m venv .venv
.venv\Scripts\Activate.ps1
python -m pip install -r backend/requirements-test.txt
```

### macOS / Linux

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r backend/requirements-test.txt
```

Файл `backend/requirements-test.txt` должен содержать:

```
openai
python-dotenv
jsonschema
pandas
pypdf
pymupdf
```

Если при запуске видите `ModuleNotFoundError`, окружение не активировано или библиотека не установлена: выполните `pip install <имя>` в активном `.venv`.

## 2. Ключ

Скопируйте `backend/.env.example` в `backend/.env` и вставьте выданный команде ключ.

```powershell
Copy-Item backend/.env.example backend/.env
```

```bash
cp backend/.env.example backend/.env
```

В `backend/.env` замените `PASTE_TEAM_KEY_HERE` на настоящий ключ. Остальные значения уже заданы:

```
LLM_API_KEY=PASTE_TEAM_KEY_HERE
LLM_BASE_URL=https://changellenge.up.railway.app/v1
LLM_MODEL=qwen/qwen3.6-35b-a3b
```

Не отправляйте ключ в чаты и не коммитьте его. `backend/.gitignore` исключает `.env` из Git, но проверьте это сами перед первым коммитом.

## 3. Порядок проверки

Команды выполняются из корня проекта. Идите сверху вниз: сначала бесплатные, потом платные.

### Шаг 1. Подключение и режим рассуждений

```bash
python backend/scripts/test_connection.py --try-all
```

Скрипт отправит 5 коротких запросов: без параметров и с каждым из четырёх способов отключить рассуждения (`openrouter`, `effort`, `qwen`, `flat`). В итоговой таблице нужен стиль, у которого `reasoning` равен 0.

Для шлюза организаторов результат такой:

| Стиль | reasoning_tokens | Время |
|---|---|---|
| none (по умолчанию) | 247 | ~5 с |
| `openrouter` | 0 | ~1 с |
| `effort` | 0 | ~1 с |
| `qwen` | 191, шлюз игнорирует | ~5 с |
| `flat` | 273, шлюз игнорирует | ~3 с |

Рабочие способы: `--think-style openrouter` и `--think-style effort`. Если у вас таблица другая, используйте свой результат.

Простой запуск одного запроса без перебора:

```bash
python backend/scripts/test_connection.py
```

### Шаг 2. Данные организаторов (бесплатно)

Положите CSV и PDF в `data/`, оригиналы не меняйте.

```bash
python backend/scripts/test_csv.py data/имя_файла.csv
python backend/scripts/test_csv.py data/имя_файла.csv --rows 5000
python backend/scripts/test_pdf_text.py data/имя_файла.pdf
python backend/scripts/test_pdf_text.py data/имя_файла.pdf --pages 10 --show-text
```

- `test_csv.py` читает до 1000 строк (меняется через `--rows`), пробует кодировки `utf-8-sig`, `cp1251`, `utf-8`, сообщает о пустом файле, колонках без названия и дублях.
- `test_pdf_text.py` проверяет первые 5 страниц (меняется через `--pages`). Если текст не извлекается, PDF может быть сканом или графиком-картинкой. Это не значит, что документ пустой.

### Шаг 3. Бизнес-анализ по контракту

```bash
python backend/scripts/test_business_analysis.py --no-think --think-style openrouter
```

Скрипт отправляет синтетическое событие и профиль компании, получает JSON и проверяет его по схеме `BusinessAnalysis 1.0`. Коды возврата: `0` успех, `1` ошибка запроса, `2` невалидный JSON, `3` JSON не соответствует схеме, `4` пустой ответ.

Полезные флаги:

| Флаг | Назначение |
|---|---|
| `--no-think` | отключить рассуждения (стиль задаётся `--think-style`) |
| `--max-tokens N` | лимит токенов ответа, по умолчанию 4000 |
| `--no-example` | не добавлять в промпт пример формы ответа, собранный из схемы |
| `--no-response-format` | не передавать `response_format=json_object` |
| `--model ID` | другая разрешённая модель |
| `--show-prompt` | напечатать системный промпт без запроса к API |

Режим с рассуждениями (если нужно глубже анализировать):

```bash
python backend/scripts/test_business_analysis.py --max-tokens 10000
```

Что выяснено на синтетическом кейсе «ключевая ставка сохранена»:

| Режим | Время | Токенов ответа |
|---|---|---|
| С рассуждениями | ~38–40 с | 2900–4400 |
| `--no-think --think-style openrouter` | ~5 с | ~400 |

Без рассуждений ответ быстрее и дешевле в 7–8 раз и проходит схему, но качество ниже: списки `impact_mechanisms`, `risks`, `opportunities` могут получиться пустыми, а релевантность заниженной. Выбор режима нужно делать по содержанию ответов, а не только по валидности схемы.

### Шаг 4. Вызов инструмента

```bash
python backend/scripts/test_tool_call.py
```

Успех: в ответе есть `tool_call` функции `get_company_profile` с аргументом `company_id`. Функция не выполняется и данные не читаются. Если шлюз отклоняет `tools` или `tool_choice`, это не доказывает, что модель в принципе не умеет работать с инструментами.

### Шаг 5. Страница PDF как изображение

Определите номер страницы с графиком (нумерация с 1):

```bash
python backend/scripts/test_pdf_chart_vision.py data/имя_файла.pdf --page 4 --think-style openrouter
```

Дополнительно: `--model ID`, `--zoom 1.5`, `--max-tokens 1500`. Запрос платный. Если API вернул ошибку про формат изображений, сохраните её текст и не повторяйте запрос много раз: шлюз может не поддерживать image input, даже если модель его поддерживает.

### Шаг 6. Сравнение моделей

```bash
python backend/scripts/compare_models.py --models qwen/qwen3.6-35b-a3b --cases loan_exposure
python backend/scripts/compare_models.py
python backend/scripts/compare_models.py --think-style openrouter --max-tokens 4000 --show
```

Скрипт сначала показывает количество запросов и просит ввести `yes`. Без аргументов запускает 5 моделей × 2 кейса = 10 запросов. Результаты сохраняются в `backend/test_results/model_comparison.json` (там нет ключа API), в консоль выводится сводка: валидность схемы, время, токены, рассуждения, стоимость.

Стиль отключения рассуждений подходит не обязательно всем трём моделям. Ошибка по одной модели не останавливает остальные запросы.

Сравнивайте не только валидность схемы: использует ли модель признаки компании, отделяет ли факты от предположений, указывает ли неизвестные данные.

## Бюджет

- Лимит 500 рублей в день общий для всей команды и всех моделей.
- Единицы поля `cost` в ответе шлюза не задокументированы. Прежде чем запускать серии запросов, уточните у организаторов, в чём оно измеряется.
- Примерный расход одного запроса: ~0,001 (короткий, без рассуждений), ~0,05 (бизнес-анализ без рассуждений), ~0,3–0,45 (бизнес-анализ с рассуждениями).
- Начинайте с бесплатных проверок и `test_connection.py`. Сравнение моделей и тест изображения запускайте осознанно. Не запускайте платные тесты в цикле.

## Если что-то не работает

| Симптом | Причина и решение |
|---|---|
| `ModuleNotFoundError` | не активировано `.venv` или не установлена библиотека: `pip install -r backend/requirements-test.txt` |
| «API-ключ не настроен» | не создан `backend/.env` или в нём остался `PASTE_TEAM_KEY_HERE` |
| Пустой `content`, `finish_reason: length` | рассуждения израсходовали весь `max_tokens`: добавьте `--no-think --think-style openrouter` или увеличьте `--max-tokens` |
| JSON обрывается на середине | то же самое: ответ упёрся в лимит токенов |
| `{"...": "..."}` вместо анализа | модель не справилась со схемой без рассуждений: проверьте, что не передан `--no-example`, и смотрите промпт через `--show-prompt` |
| JSON валиден, но поля пустые | схема допускает пустые списки; нужен более жёсткий промпт или согласованное изменение контракта |
| Ошибка про `reasoning` / неизвестный параметр | шлюз не принимает этот стиль: выберите другой по таблице из шага 1 |
| Таймаут | запросы с рассуждениями идут до минуты; таймаут клиента 120 с, повторять запросы подряд не нужно |

Если ошибка остаётся, пришлите название модели и текст ошибки, удалив ключи, персональные данные и прочие секреты.

## Важные замечания

- Не добавляйте в Git ключ и исходные данные организаторов, если правила не требуют обратного. Папку `backend/test_results/` тоже лучше не коммитить.
- Скрипты не являются готовым production-анализатором и не подключены к frontend: это отдельный этап после выбора модели и режима.
- Валидный JSON не означает правильный анализ: содержание ответов нужно проверять вручную.
