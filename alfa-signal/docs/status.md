# Альфа Сигнал — где мы сейчас

*Обновлено после PR #18 (с доработкой: свежесть и противоречащие прогнозы). Документ для команды: что уже сделано, как это закрывает требования кейса
и что осталось до сдачи.*

## Коротко

Каркас решения собран целиком и работает от начала до конца: лента новостей под компанию →
клик → агент разбирает событие с опорой на данные компании и аналитику Альфа-Банка →
карточка с источниками, ходом анализа и чатом. Всё это проверено автотестами (256 на backend),
прогоном в браузере и **прогоном агента на реальной модели**: 6 разборов из 6 прошли проверку,
позиция банка найдена во всех (подробно — «Прогон на реальной модели» ниже). Все 64 страницы PDF
Альфа-Банка распознаны, в поиске 251 фрагмент.

Backend-тесты, frontend-проверки и production-сборка автоматически запускаются в GitHub Actions
для каждого push и pull request.

Главное, что осталось:
1. **Разметка релевантности для реальных демо-компаний** — её добавляет команда данных.
2. **Устойчивость на свежих новостях** — 3–5 новостей через «Разобрать новость».
3. **Финальная сдача** — контрольный commit/tag и проверка чистого Docker-запуска.

Обозначения: ✅ сделано · 🟡 сделано, но не проверено на реальной модели или сделано частично ·
❌ не сделано.

## Что изменилось — по шагам

### 1. Единый формат ответа и надёжная работа с моделью (PR #1–2)
**Было.** Три разных формата ответа (схема в `docs/contracts`, Pydantic-модель и промпт)
не совпадали между собой; ответ модели мог «развалиться» на любой лишней кавычке; каждый
повторный запрос стоил денег.

**Сделали.**
- Контракт инсайта v2 (`backend/app/ai/schemas.py`): каждое утверждение помечено, на чём оно
  основано — **факт** (новость или данные компании), **аналитика банка**, **вывод модели** или
  **гипотеза** — и ссылается на конкретные доказательства. Схема сама отклоняет факт без
  источника и «позицию банка» без документа банка.
- Один клиент для всех запросов к модели (`backend/app/llm/`): JSON-режим, отключение
  «рассуждений», проверка ответа, одна попытка исправления, кеш (повтор бесплатный), суточный
  лимит запросов и журнал каждого вызова со стоимостью.

**Закрывает:** критерии 03 (видно, где позиция банка, а где AI) и 04 (связь выводов с первоисточниками), ограничение бюджета 500 ₽/день.

### 2. Новости превращаются в события (PR #3)
**Было.** Новости собирались, но не классифицировались: у реальной новости каналы влияния
были пустыми, поэтому ни одна не совпадала с признаками компании.

**Сделали.** `extract_event` определяет тип события, каналы влияния (ставка, депозиты, лизинг,
внешняя торговля, валюта, инфляция…), отрасль (разделы ОКВЭД), страны, регионы и факты из
текста. Работает через модель, а если модель недоступна — по ключевым словам, бесплатно.
Числа в фактах сверяются с текстом новости. Релевантность теперь учитывает и отрасль, регион,
страну ФТС компании.

**Закрывает:** критерии 01 (отбор событий под компанию), 04 (обработка материалов), 05 (новые
новости без заранее подготовленных сценариев).

### 3. Аналитика Альфа-Банка (PR #4, #7–#9)
**Было.** Документы банка в решении не использовались. Выяснилось, что все PDF кейса — сканы
без текста.

**Сделали.**
- Реестр 9 документов с датами и темами; файлы находятся в `data/raw` по имени.
- Распознавание сканов разрешённой моделью Qwen3-VL: постранично, с сохранением после каждой
  страницы, с автостопом при недоступном шлюзе, с распознаванием по половинам для тяжёлых
  страниц, без «мусора» из подписей осей графиков.
- Поиск по фрагментам (BM25, без внешних сервисов) со ссылкой на документ и страницу. Если
  подходящего тезиса нет — честное «позиция банка не установлена».

**Закрывает:** критерий 03 и ограничение «аналитика банка должна быть заметной частью ценности».

### 4. Агент (PR #5)
**Было.** Один запрос к модели — «прочитай и напиши вывод».

**Сделали** (`backend/app/agents/`). Агент сам составляет план, вызывает инструменты (профиль
компании, связи и группа, релевантность, поиск по аналитике банка), пишет анализ, затем
**проверяет его правилами**: нет ли чисел без источника, опираются ли причины на признаки
компании, подтверждается ли тезис банка текстом документа, не выдана ли сумма платежей за
выручку. По замечаниям агент решает: поискать ещё (например, переформулировать запрос к
документам банка), переписать анализ или остановиться. Каждый шаг пишется в журнал, который
виден пользователю в блоке «Ход анализа».

**Закрывает:** критерии 02 (содержательная интерпретация с несколькими факторами), 11 (агентная
логика), 12 (трассируемость), требования к агентной логике со стр. 7.

### 5. API, хранилище, чат (PR #5)
**Было.** У backend был только список компаний.

**Сделали.** Эндпоинты ленты, анализа, карточки, журнала агента, чата, отзывов, документов
банка и статуса (`docs/api.md`); хранение в SQLite; загрузка новости по ссылке с защитой от
запросов во внутреннюю сеть; чат уточнений со сценарным расчётом («что если ставка снизится
на 1 п.п. при долге 500 млн») — числа берутся только из вопроса пользователя.

**Закрывает:** критерии 06 (полный сценарий) и 10 (уточняющий вопрос, другой разрез, переход к
первоисточнику), требования безопасности (стр. 12).

### 6. Интерфейс подключён к данным (PR #6)
**Было.** Все экраны показывали захардкоженные демо-тексты.

**Сделали.** Лента и компании берутся из API; событие разбирается по клику (так решила
команда, чтобы не тратить бюджет); «Разобрать новость» по ссылке или тексту; карточка строится
из данных: эффект, цепочка влияния, факты, риски и возможности, позиция банка со ссылкой на
страницу PDF, чат, «Ход анализа», отзыв. Вёрстка участника 3 сохранена, демо-режим остался.

**Закрывает:** критерии 06 (полный сценарий), 09 (точка входа — частично), 10.

### 7. Данные, качество, документация (PR #5–#6)
- Синтетические данные для жюри (`data/synthetic/`): 6 компаний, платежи, 10 новостей,
  ручная разметка релевантности.
- Подбор контрастных демо-компаний из реальных данных: `pick_demo_companies.py`
  (выручка в рублях; 102 клиента с выручкой > 15 млрд).
- Оценка качества `run_eval.py` (критерий 08): доля проверенных инсайтов, найденной позиции банка, чисел без
  источника, различие выводов разных компаний, точность ленты.
- README, lock-файлы, THIRD_PARTY_NOTICES, описание агента и API, пошаговая проверка.

### 8. Прогон на реальной модели и доработки (PR #11–#12)
- Все 9 PDF банка (64 страницы) распознаны вручную по сканам и загружены как готовые страницы
  (`method: manual`); конвейер распознавания через Qwen3-VL остаётся для новых документов.
- Проверка чисел больше не принимает идентификатор компании (`U_9250`) за выдуманное число;
  год без источника — предупреждение, а не блокирующая ошибка.
- FACT с явным выводом («поэтому», «может») код сам переводит в AI_INFERENCE, без лишней итерации.
- При замечаниях только к тексту агент сразу переписывает анализ, без запроса к LLM на решение
  и без повторного поиска по аналитике, который не даёт новых фрагментов.
- `demo_scenario.py --force` — пересчитать анализ, даже если он уже сохранён.

### 9. По итогам вебинара организаторов (PR #14–#18)
Подробные отчёты — `docs/reports/01`–`05`.
- **Данные** (`docs/data.md`): выручка группы (крупный бизнес по группе), связи через физлиц как гипотезы,
  отрасли контрагентов по платежам; дисклеймер «не является инвестиционной рекомендацией».
- **Склейка публикаций** (`docs/news-dedup.md`): ссылка, текст, близость TF-IDF, LLM для спорных пар;
  запреты по процентам, датам, участникам; 14 из 14 контрольных пар.
- **Скоринг 0–100** (`docs/scoring.md`): пять групп факторов, сумма = балл, уровни определены;
  Precision@5 на синтетике 0,71 → 0,80.
- **Действия пользователя:** заявки менеджеру и аналитику, скрытие событий, профиль компании и данные
  от пользователя, выбор роли.
- **Сбор по расписанию и сводка** (`docs/news-collection.md`): RSS по расписанию и по кнопке, предварительный
  анализ важного с лимитом, «Главное за сутки», демо-вход, `profile_data.py`.
- **Свежесть и противоречия** (`docs/reports/06`): порядок ленты «балл × свежесть», отсечка публикаций старше
  7 дней, свежие обзоры банка выше; прогнозы банка из таблиц с пересмотрами (ставка 13,5% → 14,0%),
  инструмент `get_bank_forecasts` и проверка `outdated_bank_forecast` (закрывает T05).

## Прогон на реальной модели

`run_eval.py --companies U_9250 U_57706 U_177581 --max-events 2` (модель `qwen/qwen3.6-35b-a3b`,
до доработок PR #12):

| Метрика | Значение | Что значит |
|---|---|---|
| Разборов | 6 | по 2 самых релевантных события на 3 компании |
| Успешных | 100% | агент вернул инсайт во всех случаях |
| Прошли проверку (`verified`) | 100% | нет чисел без источника, тезисы банка подтверждены текстом |
| Нужна повторная итерация | 33% | 2 из 6 разборов исправлялись после проверки |
| Позиция банка найдена | 100% | в каждом разборе есть тезисы из аналитики Альфа-Банка со страницей |
| Чисел без источника | 0 | |
| Разные выводы для разных компаний | 100% пар | одно событие → другой тип влияния или оценка |
| Общие признаки компании в паре | 0,375 | у разных компаний выводы опираются на разные данные |
| Вызовов инструментов | 4,3 в среднем | |
| Время | ~38 с на разбор | |
| Стоимость | 16 запросов, 2,26 ₽ на 6 разборов | ≈ 0,4 ₽ и 2–3 запроса на разбор |

Пример персонализации — событие «Банк России сохранил ключевую ставку на уровне 14%»:
- U_9250 (инженерное строительство, кредиты и лизинг): дорогие заёмные средства сдерживают
  проекты и рефинансирование; оценка 75.
- U_57706 (депозиты и лизинг): эффект разнонаправленный — доход по депозитам растёт, лизинг
  дорожает; оценка 85.

Чат уточнений на вопрос «Что если ставка снизится на 1 п.п. при долге 500 млн руб.?» ответил
расчётом −5 млн руб./год (считает код), с допущением о плавающей ставке (HYPOTHESIS) и списком
недостающих данных.

## Ограничения кейса (стр. 11–12)

| Ограничение | Как учтено |
|---|---|
| Не новостная лента и не пересказ | у каждого события — влияние на конкретную компанию, а не текст новости |
| Аналитика банка — заметная часть ценности | отдельный блок «Мнение банка» со ссылкой на страницу документа |
| Особенности конкретной компании, а не отрасли | причины релевантности обязаны ссылаться на признаки компании (иначе проверка не пройдена) |
| Безопасность AI | инструменты только читают; компания фиксирована запросом; текст новости — данные, а не команды; защита от SSRF; журнал вызовов (`docs/agent.md`) |
| Только разрешённые модели, 500 ₽/день | Qwen3.6 и Qwen3-VL из списка; кеш; суточный лимит; разбор только по клику |
| Неполные и шумные данные | пропуски профиля попадают в «Что пока неизвестно»; плейсхолдер выручки 1000 отбрасывается; дубли компаний исключаются |
