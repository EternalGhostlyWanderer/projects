# Отчёт 11. Ролевой слой разбора и положение компании в отрасли

## Зачем
- Задание: сервис для людей, а не для юрлиц; у одной компании несколько пользователей с разными потребностями.
  Роль уже меняла порядок ленты и акценты чата, но сам разбор был одинаковым для финдиректора и бухгалтера.
- Задание, п. 1: «положение компании и/или группы в отрасли и доля рынка» — не было сделано.

## Что сделано
- **Ролевой слой** (`app/agents/role_view.py`): «Что это значит для вас» — главное для роли, 2–3 вывода, порядок
  рисков и шаги этой роли. Отдельный короткий запрос к модели поверх готового разбора (около 0,1 ₽), проверка:
  только доказательства разбора и никаких новых чисел. Без LLM — по правилам. Хранится по паре «разбор × роль».
  `GET /api/v1/insights/{id}/role-view`.
- **Положение в отрасли** (`app/modules/companies/position.py`): место по выручке среди компаний того же класса
  ОКВЭД в выборке банка, перцентиль, доля в выручке отрасли по выборке, уровень (лидер, крупный, средний,
  небольшой), то же для группы. В профиле, в доказательствах агента (`company.position`) и в интерфейсе.
- **Фронтенд**: блок «Что это значит для вас» на странице разбора, строка «Положение в отрасли» в профиле.

## Проверка
- `tests/test_role_view.py` (6): ролевой блок через модель, отклонение выдуманных чисел и чужих рисков с повтором,
  правила без LLM, кеш по роли в API, место и доля в отрасли, группа, ненадёжные случаи (мало компаний, заглушка
  выручки). Всего 206 OK; frontend `npm run check` OK.
- На синтетике в каждом классе ОКВЭД меньше пяти компаний — позиция `too_few_peers`; на реальных данных
  посчитается. Проверить у себя: `http://localhost:8000/api/v1/companies/U_9250/profile` → `industry_position`.

## Ограничения
- Доля — по клиентам и потенциальным клиентам банка в выборке, а не по рынку; так и подписано.
- Ролевой блок готовится при открытии разбора; заранее (в предварительном анализе) — пока нет.
