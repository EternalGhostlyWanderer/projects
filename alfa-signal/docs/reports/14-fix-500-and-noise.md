# Отчёт 14. Ошибка 500 при анализе, шум классификации, docker-compose

## Что нашла проверка 26 октября
- `POST /insights/analyze` → HTTP 500, а после него и лента компании → 500.
- После входа фоновый сбор сам запускал платный предварительный анализ для активных компаний.
- В ленте шум: «на ЕГЭ не спросят» — «потребительский спрос»; визы в Черногорию и аккредитация СМИ — внешняя
  торговля для любой компании с ВЭД.

## Причина 500
Автоисправление ответа модели (`repair_draft`, отчёт 9) меняло метку тезиса позиции банка, сославшегося на новость,
на AI_INFERENCE — а в `bank_view` допустим только BANK_ANALYSIS. Такой разбор сохранялся (исправление шло без
повторной проверки) и затем не проходил проверку при ответе API и при чтении ленты.

## Исправлено
- `repair_draft`: тезис банка без материала банка убирается из `bank_view`; если тезисов не осталось — `not_found`.
  После исправления ответ заново проверяется на соответствие контракту; если не прошёл — повторный запрос к модели.
- Хранилище: сохранённый разбор, который не проходит проверку контракта, пропускается с предупреждением в журнале,
  а не роняет ленту. Уже испорченная запись в базе больше не мешает.
- Предварительный анализ для активных пользователей — только при `PREANALYZE_ACTIVE=1`.
- Классификация: «спрос» — только существительное, не глагол «спросить».
- Скоринг: новость о внешней торговле без названной страны — 10 баллов вместо 20 (ниже порога ленты, если других
  признаков нет).
- Демо-пользователь `demo` — «Пример Примерович».
- `docker-compose.yml`: проброшены `API_REQUIRE_COMPANY_SCOPE`, `DEMO_COMPANY_IDS`, `NEWS_OFFICIAL_SOURCES`,
  расписание сбора, `PREANALYZE_ACTIVE`, `DEMO_SNAPSHOT_FILE`, `DEMO_USERS`; RSS Мосбиржи заменён экономическими рубриками.

## Проверка
Новые тесты в `test_real_news_fixes.py` (4) и `test_scheduler.py`. Всего 225 OK. Лента на синтетике: P@5 0,80 — без изменений.

## Второй случай (26 октября, после #27)
Лента снова падала с ошибкой «event_summary допускает только утверждения FACT». Причина — `relabel_inferred_facts`
(отчёт 4): FACT со словами «может», «поэтому» перемечался в AI_INFERENCE и в блоке «Что произошло», где по контракту
допустим только FACT. Исправлено: «Что произошло» не перемечается (вывод там ловит проверка `fact_contains_inference`).
Дополнительно: оркестратор проверяет итоговый разбор на соответствие контракту перед сохранением (нарушение —
честная ошибка анализа), а `save_analysis` не записывает разбор, который потом не прочитается. Уже сохранённые
испорченные разборы лента пропускает (#27) — после перезапуска сервера.
