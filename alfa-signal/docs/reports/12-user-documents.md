# Отчёт 12. Сведения о компании из документов пользователя

## Зачем
Чтобы выдача была персональной, сервис должен понимать, что важно конкретной компании, а данных банка для этого
мало. Раньше пользователь мог вручную указать долг, валюты, страны и закупки. Теперь он может загрузить документ
(договор, отчётность, описание), а также указать долю экспорта, отрасли покупателей и поставщиков, планы
и важные темы.

## Что сделано
- **Новые поля** (`user_data.py`) с источником каждого поля: вручную или из документа с цитатой.
- **Извлечение из документа** (`documents.py`): модель Gemma (роль `extract`, из разрешённого списка) предлагает
  поля с дословными цитатами. Код проверяет цитату, поле и значение. Пользователь подтверждает и сохраняет сам.
  Документ не хранится.
- **Скоринг:** группа «Интересы компании»; доля экспорта и валюты выручки — финансовые каналы; отрасли
  покупателей и поставщиков — цепочка поставок.
- **Агент:** новые сведения — доказательства «из документа пользователя» и «со слов пользователя»; проверка
  засчитывает их как признаки компании.
- **Журнал изменений** и API: `extract`, `apply-document`, `history`.
- **Фронтенд:** «Заполнить из документа», поле «Темы, важные компании», сохранённые поля с источником; исправлено
  стирание полей при сохранении формы.

## Проверка
- `tests/test_documents.py` (7): чтение TXT, PDF и ошибок; цитата обязана быть в документе; предпросмотр через модель
  с отбраковкой неверного значения; источник поля в доказательствах; скоринг по интересам, экспорту и покупателям;
  API: извлечь, применить, ручная правка без потери источника документа, журнал. Всего 213 OK; frontend OK.
- Лента на синтетике: P@5 0,80, R@5 0,945 — без изменений.
- Живая проверка у себя: профиль компании → «Заполнить из документа» → вставить абзац из отчёта.

## Ограничения
- Сканы без текстового слоя не читаются (нужно вставить текст); Word — через вставку текста.
- Отрасли покупателей и поставщиков сопоставляются с ОКВЭД по словам (как в классификации новостей).
