# Отчёт 18. Разбор новости, которую прислал пользователь

## Зачем
Пользователь может сам дать ссылку или вставить текст новости (`POST /api/v1/insights/analyze` с `url` или
`title` + `text`; форма во фронтенде уже есть). Надо было проверить, что такой разбор честный и безопасный.

## Что уже было
- Проверка ссылки от SSRF: только http(s), порты 80/443, публичные адреса. Каждый редирект проверяется заново.
- Склейка с уже собранными событиями (`register_event`) и повторное использование готового разбора (`find_insight`).

## Что сделано
- **Фильтры сбора не применяются.** Кликбейт, «не про бизнес», давность и доверие к источнику действуют только при
  сборе из лент. Пользователь сам решил, что новость важна. Это проверено тестом.
- **Полнота текста.** `NewsEvent.content`:
  - `full` — статья от 500 знаков;
  - `partial` — фрагмент или платный доступ (признаки подписки на странице);
  - `title_only` — один заголовок.

  Если текст неполный, проверка добавляет предупреждение `source_text_limited`, и статус разбора — `partial`,
  а не `verified`. Пользователь видит пояснение в замечаниях: «Разбор сделан по одному заголовку…».
- **Понятные ошибки загрузки** (HTTP 400, текст в `detail`):
  - 402/403 — «доступна только по подписке / сайт закрыл доступ — вставьте текст вручную»;
  - 404/410 — «страница не найдена»;
  - 429 — «сайт ограничил частоту»;
  - тайм-аут — «сайт не ответил за 15 секунд».

  Если у страницы есть заголовок, но нет текста, разбор делается по заголовку с пометкой `title_only`.
- **Без повторной работы.** Ссылку, которая уже есть в базе (с utm-метками или без), заново не скачиваем.
  Повторно присланный текст той же публикации не классифицируем снова. Если прислан более полный текст той же
  публикации, событие переклассифицируется, а склеенные издания сохраняются.
- **Изоляция.** `NewsEvent.submitted_by`: присланная новость видна только в ленте своей компании. Она не попадает
  в предварительный анализ других компаний и в их демо-снимок. Если ту же публикацию потом соберут из общих лент,
  новость становится общей.

## Проверка
`tests/test_user_news.py` (16): ошибки HTTP и тайм-аут, платный доступ, страница с одним заголовком, обход
фильтров, статусы `partial`/`verified`, повторная ссылка без загрузки, внутренний адрес, изоляция в ленте и снимке,
склейка с общей лентой. Тесты бэкенда: 253 OK.

## Фронтенд
Менять ничего не обязательно: замечания проверки уже показываются на странице разбора. По желанию — значок
«по заголовку» / «фрагмент» по полю `event.content` (см. `docs/team/changes-for-frontend.md`).
