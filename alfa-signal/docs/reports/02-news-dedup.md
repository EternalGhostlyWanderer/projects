# Отчёт 2. Склейка дублей новостей

## Зачем
Задача из списка P0: «объединять новости разных изданий об одном событии, сохранять все ссылки,
повторный сбор RSS не должен создавать дубль; не склеивать разные решения ЦБ и события разных дат;
не терять результаты анализа». До этого PR дубли отсекались только по совпадению ссылки и только
внутри одного сбора.

## Что сделано
- `backend/app/modules/news/clustering.py` — четыре уровня склейки (ссылка, текст, близость TF-IDF,
  LLM для спорных пар) и запреты (проценты, даты события, участники, тип события).
- Событие хранит все публикации (`sources`) и признак обновления (`has_update`); таблица псевдонимов
  `event_aliases` ведёт id дубля к каноническому событию — анализ не теряется.
- Сбор RSS отсекает дубли до классификации; `POST /events/collect` возвращает `added`, `merged`,
  `skipped_known_urls`; `load_events.py` печатает, что с чем склеено.
- `/system/status` — число склеенных публикаций.
- Карточка анализа — «Источники события (N)» со ссылками на все издания.
- `scripts/check_dedup.py` — точность и полнота склейки на контрольных парах, число дублей в хранилище.
- Описание для команды и жюри — `docs/news-dedup.md`.

## Проверка
- Контрольные пары (`data/synthetic/dedup_pairs.json`): 14 из 14, точность склейки 1,00, полнота 1,00.
  Пары нашли две ошибки первой версии — «Банк России» и «ЦБ» считались разными участниками,
  «Китайские» и «Китай» — тоже; исправлено.
- Синтетические новости (10 разных событий) не склеиваются друг с другом: максимальная близость 0,18.
- 7 новых тестов (`tests/test_clustering.py`): контрольные пары, запрет по процентам, LLM только
  для спорных пар, второе издание становится источником, повторный сбор не дублирует, id дубля ведёт
  к каноническому событию, разные события остаются раздельными. Всего 106 тестов backend проходят.

## Ограничения
- Пары собраны вручную — на реальном потоке RSS пороги стоит перепроверить (`check_dedup.py --store`).
- Участники определяются по словам с заглавной буквы в заголовке; при LLM-извлечении добавляются
  организации из сущностей события.
