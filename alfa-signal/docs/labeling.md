# Ручная разметка релевантности

## Зачем
Качество ленты пока измерено на синтетике, которую команда придумала сама, — это не доказывает, что лента
полезна реальной компании. Разметка — ответы людей «важна ли эта новость этой компании». Она даёт:
1. честную метрику для презентации (критерии 05 и 08): P@5, Recall@5 и nDCG@5 на реальных событиях;
2. настройку весов скоринга по ошибкам: где система ставит высокий балл неважному и наоборот;
3. регресс-тест: каждое изменение скоринга проверяется на том же наборе.

## Как
1. Соберите реальные новости (`load_events.py`, `docs/news-collection.md`).
2. Сгенерируйте таблицы — компании подберутся разные (отрасль, кредит, депозит, лизинг, ВЭД):
   ```powershell
   python backend/scripts/make_labeling_set.py --auto 8 --events 30 --annotators anna maria alina
   ```
   В `backend/var/labeling/`: `labeling_<имя>.csv` для каждого разметчика, `LABELING_GUIDE.md` (шкала 0–3 и
   правила), `labeling_key.json` — оценки системы (**разметчикам не показывать**).
3. Каждый открывает свой CSV в Excel (разделитель «;», UTF-8), ставит `label` 0–3 и по желанию `reason`,
   сохраняет в CSV с тем же именем. 40 пар — общие для всех: по ним считается согласие.
4. ```powershell
   python backend/scripts/score_labels.py
   ```
   Печатает согласие разметчиков (точное, ±1, взвешенная каппа), P@5, Recall@5, nDCG@5 по компаниям, сколько
   важных событий лента скрыла и сколько неважных показала, и худшие ошибки с объяснением балла.
   Отчёт — `labeling_report.json`.

Объём: 8 компаний × 30 событий = 240 пар, на троих — по ~93 пары (40 общих), 1–2 минуты на пару.
Каппа выше 0,6 — люди согласны, метрике можно верить; ниже — уточнить инструкцию и переразметить спорное.
