# Данные организаторов: как мы их читаем и чистим

Правила основаны на описании кейса (приложение 1) и ответах организаторов на вебинаре.

## Файлы
| Файл | Что в нём | Переменная окружения |
|---|---|---|
| `df_Uid_data_hack.csv` | профили юрлиц: отрасль, регион, продукты банка, ФТС, выручка, группа | `COMPANIES_CSV` |
| `df_Uid_payment_hack.csv` | платежи между компаниями: сумма и количество с 1 января | `PAYMENTS_CSV` |
| `df_Fid_Uid_link_hack.csv` | связь физлиц с компаниями | `PEOPLE_CSV` |

По умолчанию файлы ищутся в `data/raw/` (не коммитятся). Для проверки без данных организаторов —
синтетический набор `data/synthetic/` с теми же колонками.

## Очистка
| Проблема | Правило | Где в коде |
|---|---|---|
| `REVENUE_COMPANY = 1000` — техническая заглушка | считается отсутствующей выручкой, в сумму группы не входит | `links.clean_revenue` |
| один `SYNTHETIC_U` в нескольких разных строках (артефакт обезличивания) | компания исключается, число исключённых видно в `/system/status` | `repository._exclude_duplicate_companies` |
| ~82% суммы платежей — переводы компании самой себе | исключаются из контрагентов, концентрации и отраслей контрагентов; показываются отдельно | `relationships`, `exposures`, `links.counterparty_industries` |
| контрагент, которого нет в таблице юрлиц | его отрасль не восстанавливается, сумма идёт в «отрасль неизвестна» | `links.counterparty_industries` |
| одинаковые строки в связях физлиц | схлопываются | `links._people_links` |
| физлицо связано больше чем с 10 компаниями | связь не используется: скорее массовый руководитель или артефакт данных | `links.MAX_COMPANIES_PER_PERSON` |
| `CL_TYPE = PROSPECT / CLOSE_CLIENT` | сервис рассчитан на действующих клиентов: демо-компании подбираются только из `CLIENT`, в контексте есть `eligibility.supported` | `pick_demo_companies.py`, `context.py` |

## Что выводим из данных
- **Выручка группы.** Крупный бизнес определяется по выручке группы, а не отдельного юрлица
  (порог 15 млрд руб., выручка за 2025 год в рублях). Компания без группы — группа из одной себя.
  Если не у всех компаний группы есть выручка, это помечается (`revenue_complete = false`).
- **Связанные компании.** Компании той же группы (`GROUP_ID` — общее владение или управление) —
  подтверждённая связь. Компании с общим физлицом — **гипотеза** с указанием основания.
- **Отрасли контрагентов.** Доли платежей по классам ОКВЭД (первые две цифры) поставщиков и
  покупателей. Это **гипотеза о цепочке поставок**: платёж показывает финансовое взаимодействие,
  но не его характер.

Агент получает связи и отрасли контрагентов, только когда вызывает инструмент
`get_company_relations`; в доказательствах гипотезы помечены типом `HYPOTHESIS`.
